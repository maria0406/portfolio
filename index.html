02 · Problem

Prepping a set takes longer than playing it

You have to work out which songs mix well together, then decide where in each song to start the blend, when to swap the bass and when to filter out.

Why it's hard

  • rekordbox can sort by BPM or by key, but not both at once.
  • It doesn't tell you what to do at each transition.
  • Beginners learn from tutorial videos that use someone else's songs, so the timing never matches their own tracks.
03 · Who it's for

Student DJs at UT on beginner controllers

They play rekordbox on controllers like the Pioneer DDJ-FLX4 and want a set they can actually play, plus a way to learn the moves on their own tracks.

04 · What it does

Order the set, mark every transition, then teach the moves

Orders the set

Reads a playlist straight from the local rekordbox library and analyzes each track's tempo, beat grid, key, phrases and energy. Then it orders the tracks by BPM and key together, with energy shaped to a set arc.

Marks every transition

Places named, color-coded cues: MIX IN, MIX OUT, BASS SWAP, FILTER, DROP and an 8-bar safety loop. They export back to rekordbox as XML. On a 12-track test set, all 12 tracks imported with every cue at the exact time and name.

Move Coach

An animated controller in the FLX4's layout shows which knob or fader to move, which way and when, timed to the bars and phrases of the actual song. A single timing engine drives both the animation and an in-browser audio mix, so the demo you watch always matches what you hear.

Graded practice library

300 Creative Commons house tracks from 128 artists, scored on how hard they are to mix (intro and outro length, tempo stability, energy changes). They're split into 5 levels and paired into lessons, from "your first blend" to "hard transitions".

05 · How I built it

Local-first, legally sourced, tested against rekordbox itself

Stack

Python with FastAPI, librosa for audio analysis and pyrekordbox to read the rekordbox database. The front end is vanilla JavaScript, SVG and the Web Audio API. Everything runs locally, so music never leaves the DJ's laptop.

Research first

I compared where a learning tool could legally get DJ-ready audio: Creative Commons libraries, research datasets, streaming partner programs and royalty-free catalogs. Most major catalogs forbid analyzing or redistributing their tracks, so I built on Creative Commons netlabel releases from the Internet Archive.

Tested against the real thing

I imported the generated cues into rekordbox 7 and checked them against its database. That turned up four real problems, all fixed. After the fixes, a 12-track set imported with every cue at the exact time and name.

Cue placement ran past the end of short tracks.
rekordbox silently drops a cue when two share the same timestamp.
Tempo detection only resolved about 3 BPM steps. Fixed by fitting tempo to the detected beats.
Importing overwrote rekordbox's own BPM values.

Scope decision

I cut the Spotify integration because Spotify's developer policy forbids analyzing its audio. That simplified the app to no login and no tester cap.

Quality

94 automated tests covering analysis, ordering, cue placement, XML export, licensing rules and the coaching timeline.

01 · ARCA

ARCA

Automatic root cause analysis for a home-battery fleet. ARCA classifies each fault, proposes the cheapest safe fix, and pages a person only when a decision needs human judgment.

02 · Problem

When a home battery faults, both usual options are bad

Base Power runs a growing fleet of home batteries in Texas. When one faults, the usual options are a truck roll before anyone knows the cause, which is slow and expensive, or waiting until the problem gets serious, which is risky. Neither scales as the fleet grows.

03 · What it does

From telemetry to a closed case, with a person approving every step

  1. Detect

    Deterministic detectors assign each fault to one of a fixed set of root causes: thermal event, firmware mismatch, wiring or install error, or hardware defect.

  2. Diagnose

    It writes a hypothesis for the root cause. By default this comes from the detectors, and it can switch to a live LLM call when an API key is set.

  3. Plan behind a policy gate

    A planner proposes the cheapest safe fix, and a deterministic gate controls who can approve what. Cases that are thermal or have an unknown cause are blocked from any remote action.

  4. Human in the loop

    Staff approve or reject each step. Approving a dispatch schedules a technician visit with a safety checklist.

  5. Audit

    Every diagnosis, approval and outcome goes on the case timeline, and an engineer closes the case out.

  6. Score itself

    The results are checked against the known answers for a test fleet.
